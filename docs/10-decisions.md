# 技术与产品决策记录

## 2026-10-31：独立创建新项目

### 背景

现有项目 `english-speaking-interactive-book` 是英语口语互动书，目标是口语训练。

中考冲刺项目需要支持多学科题库、判分引擎、掌握度系统、错题复盘和模考。

### 决策

创建独立项目：

```text
zhongkao-sprint-book
```

### 原因

1. 产品目标不同。
2. 数据模型不同。
3. 交互复杂度不同。
4. 后续内容规模不同。
5. 版本节奏和部署策略不同。

---

## 2026-10-31：使用 Vite + React + TypeScript

### 决策

使用 Vite、React 和 TypeScript。

### 原因

1. Vite 开发体验好。
2. React 组件化适合题目、报告、错题本等界面。
3. TypeScript 能约束题目结构和判分结果。
4. 便于后续从 MVP 扩展到多学科。

### 代价

1. 相比纯 HTML 多一层构建。
2. 部署前必须 build。
3. GitHub Pages 需要处理子路径 `base`。

---

## 2026-10-31：第一版使用 localStorage

### 决策

第一版学习记录保存到 `localStorage`。

### 原因

1. 不需要后端。
2. 不需要账号系统。
3. 部署简单。
4. 适合快速验证学习闭环。

### 限制

1. 不能跨设备同步。
2. 存储容量有限。
3. 清理浏览器数据会丢失进度。

### 后续方向

题量和记录变多后迁移到 IndexedDB。

---

## 2026-10-31：先做数学试点

### 决策

MVP 先用数学示例题验证核心流程。

### 原因

1. 数学题目结构复杂，能更早暴露判分和交互问题。
2. 数学冲刺需求明确。
3. 考点树相对容易结构化。
4. 可以验证公式、表达式、多步题和几何题路线。

---

## 2026-10-31：第一版不引入路由库

### 决策

当前用组件状态切换页面。

### 原因

1. MVP 页面少。
2. 减少依赖。
3. 快速验证核心体验。

### 后续方向

页面数量增加后使用 hash router，避免 GitHub Pages 子路径刷新问题。
