# 技术与产品决策记录

## 2026-10-31：独立创建新项目

### 背景

现有项目 `english-speaking-interactive-book` 是英语口语互动书，目标是口语训练。

中考冲刺项目需要支持多学科题库、判分引擎、掌握度系统、错题复盘和模考。

### 决策

创建独立项目：

```text
zhongkao-sprint-book
```

### 原因

1. 产品目标不同。
2. 数据模型不同。
3. 交互复杂度不同。
4. 后续内容规模不同。
5. 版本节奏和部署策略不同。

---

## 2026-10-31：使用 Vite + React + TypeScript

### 决策

使用 Vite、React 和 TypeScript。

### 原因

1. Vite 开发体验好。
2. React 组件化适合题目、报告、错题本等界面。
3. TypeScript 能约束题目结构和判分结果。
4. 便于后续从 MVP 扩展到多学科。

### 代价

1. 相比纯 HTML 多一层构建。
2. 部署前必须 build。
3. GitHub Pages 需要处理子路径 `base`。

---

## 2026-10-31：第一版使用 localStorage

### 决策

第一版学习记录保存到 `localStorage`。

### 原因

1. 不需要后端。
2. 不需要账号系统。
3. 部署简单。
4. 适合快速验证学习闭环。

### 限制

1. 不能跨设备同步。
2. 存储容量有限。
3. 清理浏览器数据会丢失进度。

### 后续方向

题量和记录变多后迁移到 IndexedDB。

## 2026-10-31：第一版不引入路由库

### 决策

当前用组件状态加 URL Hash 切换页面。

### 原因

1. MVP 页面少。
2. 不引入额外路由依赖。
3. Hash 路由刷新后可保留页面。
4. 更适配 GitHub Pages 子路径部署。

### 后续方向

页面数量和参数复杂度增加后，再评估正式路由库。

## 2026-10-31：使用 KaTeX 渲染数学公式

### 决策

引入 KaTeX，并用 `MathText` 组件统一渲染 `$...$` 片段。

### 原因

1. 中考数学内容包含大量公式。
2. KaTeX 渲染速度快。
3. 内容文件可以保留纯文本数学表达式。
4. 避免学生看到原始 LaTeX 字符串。

### 代价

1. 构建产物中包含 KaTeX CSS 和字体。
2. 当前产物体积明显增大。
3. 后续需要评估按需加载或字体裁剪。

## 2026-10-31：掌握度使用简化加权模型

### 决策

第一版掌握度公式：

```text
mastery = accuracy × 65% + coverage × 25% + stability × 10%
```

### 原因

1. 计算简单，学生容易理解。
2. 不需要后端和复杂统计模型。
3. 能同时反映正确率、做题覆盖和连续答对稳定性。
4. 可以快速支撑首页薄弱点排序和考点地图。

### 限制

1. 没有时间衰减，旧记录和新记录权重相同。
2. 没有题目难度权重。
3. 没有按题型拆分掌握度。
4. 连续答对稳定性只是基础近似。

### 后续方向

引入近期窗口、时间衰减、难度权重和题型权重，并保留可解释的掌握度分。

## 2026-10-31：错题复习采用固定间隔队列

### 决策

复习间隔采用：

```text
当天 → 1 天 → 2 天 → 4 天 → 7 天 → 15 天
```

### 原因

1. 规则简单，学生能预测下次复习时间。
2. 不依赖后端定时任务。
3. 可根据 `nextReviewAt` 在前端判断到期状态。
4. 足够支撑第一版冲刺错题闭环。

### 升级规则

- 连续答对 2 次，复习阶段 +1。
- 再次错误，阶段重置为 0。
- 连续答对 3 次且达到阶段 3，标记为已掌握。

### 限制

还没有根据考点权重、错误类型和考试日期动态调整间隔。

## 2026-10-31：表达式题区分解集判分与文本判分

### 决策

表达式题新增：

```ts
answerKind?: "solution-set" | "text";
```

未填时默认 `solution-set`。

### 原因

方程解可以忽略顺序和书写形式：

```text
x = 2 或 x = 3
2,3
x1=2,x2=3
```

但下面两题不能只比较数字集合：

```text
x >= -3
x <= -3
```

因此因式分解、不等式解集、概率分数等题必须使用 `text`。

### 限制

仍然不是完整数学表达式等价判断，后续需要表达式树或专业数学判定库。

## 2026-10-31：第一版每日计划采用状态驱动规则

### 决策

每日任务不由人工固定排班，而是根据当天状态生成：

1. 到期错题优先。
2. 掌握度最低的两个考点优先。
3. 提供一次限时模考任务。
4. 保留每日复盘任务。

### 原因

1. 学生不需要自己决定“今天练什么”。
2. 规则可解释，不依赖黑盒推荐。
3. 状态变化后能快速反映到首页。
4. 可以先用本地数据验证计划质量。

### 限制

还没有根据中考日期、可用时间和目标分数做长周期排程。

## 2026-10-31：模考会话独立于学习进度存储

### 决策

未完成模考和模考历史分别使用独立 localStorage key：

```text
sprintbook-active-exam-v1
sprintbook-exam-history-v1
```

### 原因

1. 学习进度和考试会话生命周期不同。
2. 未完成试卷需要随时恢复。
3. 最近成绩需要独立保留最近 20 次。
4. 清空学习进度时可以单独处理模考数据。

### 限制

当前只支持单设备本地保存，不支持跨设备恢复。

## 2026-10-31：分区试卷采用每区独立分值

### 决策

试卷支持 `sections`，每个分区使用独立 `scorePerQuestion`。

### 原因

1. 基础题和中档题、压轴题的价值不同。
2. 分区报告能更准确反映不同能力层的表现。
3. 便于后续演化为标准中考分区。
4. 不需要立刻引入复杂矩阵组卷。

### 去重规则

试卷分区可以引用同一道题用于结构分析，但整卷题目会去重展开；整卷总分按去重后的最后一次分区结果计算。

### 限制

当前还不是标准中考官方分区和分值，后续需要模板化处理。

---

## 2026-10-31：掌握度加入时间衰减和难度调整

### 决策

单题正确率先按作答时间衰减：

```text
3 天内 1.0
7 天内 0.8
14 天内 0.55
30 天内 0.3
更早 0.12
```

考点层再按难度调整：

```text
难度调整 = 平均((难度 - 3) × 4%)
```

### 原因

1. 最近作答比一个月前的作答更能反映当前状态。
2. 正确完成较难题应比正确完成简单题更有价值。
3. 可解释性强，学生和教师能理解结果。

### 限制

这是线性近似模型，还没有基于大样本数据校准题目难度和区分度。
