# 内容运营与题库更新

## 原则

题库全面性不是靠一次写完，而是靠持续维护。

核心流程：

```text
知识地图 → 覆盖矩阵 → 内容录入 → 自动校验 → 人工审核 → 发布 → 数据反馈 → 修订
```

## 知识点树

先定义课程知识树，再挂题目。

示例：

```text
数学
├── 数与式
├── 方程与不等式
├── 函数
├── 几何
└── 统计与概率
```

每个知识点必须有唯一 ID。

## 覆盖矩阵

每个考点应检查：

```text
知识点 × 题型 × 难度
```

建议最低标准：

| 考点类型 | 最低题量 | 最低题型数 |
| --- | ---: | ---: |
| 高频考点 | 30 | 3 |
| 中频考点 | 15 | 2 |
| 低频考点 | 5 | 1 |

## 题目录入要求

已发布题目必须有：

```text
id
subject
knowledgePointIds
displayType
interactionType
difficulty
stem
answer
explanation
source
status
```

难题和高错误率题建议还必须有：

```text
完整步骤
常见错误
更优方法
相关考点
```

## 内容状态

```text
draft      草稿
reviewing  审核中
verified   已校对
published  已发布
deprecated 已下架
```

## 更新流程

```text
1. 收集来源
2. 判断是否适合目标中考
3. 改编或录入
4. 标注知识点
5. 标注题型和难度
6. 配置答案与判分
7. 补充解析
8. 自动校验
9. 人工审核
10. 发布
11. 更新覆盖率报告
```

## 自动校验

当前已添加：

```bash
npm run validate:content
npm run report:coverage
```

后续应增加：

```bash
npm run check:duplicate
```

检查项：

1. JSON 格式正确。
2. 内容文件有版本号。
3. 必填字段完整。
4. 知识点 ID 唯一。
5. 题目 ID 唯一。
6. 知识点 ID 存在。
7. 答案可判分。
8. 题干公式 `$` 符号配对。
9. 解析公式 `$` 符号配对。
10. 选项公式 `$` 符号配对。
11. 表达式题 `answerKind` 合法。
12. 暂无题目的知识点输出警告。
13. 覆盖率报告统计题量、题型、难度和考点缺口。
14. 试卷必填字段完整。
15. 试卷 ID 唯一。
16. 试卷引用题目存在。
17. 试卷内题目 ID 不重复。
18. 分区至少 3 题。
19. 试卷至少 5 题。
20. `level` 有效。

待实现：

1. 图片和音频资源存在。
2. 已发布题必须有完整解析。
3. 题干查重。
4. 难度目标覆盖率。
5. 认知层级覆盖率。

## 自动化测试

内容变更和业务规则修改后运行：

```bash
npm test
```

当前测试覆盖：

1. 判分引擎。
2. 分区试卷评分。
3. 模考趋势。
4. 掌握度时间衰减和难度调整。
5. 错题复习调度。

## 线上反馈

题目上线后关注：

```text
错误率
放弃率
平均用时
重复错误率
解析点击率
用户反馈
```

如果某题错误率过高，应检查：

1. 题目是否超纲。
2. 题干是否有歧义。
3. 难度是否标注错误。
4. 解析是否跳步。
5. 是否缺少前置铺垫题。

## 版本管理

题库发布应带版本：

```json
{
  "version": "math-2026.11.01",
  "added": 42,
  "updated": 18,
  "removed": 3
}
```

如果启用 PWA，缓存版本应同步更新。
